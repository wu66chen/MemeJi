# ADR-0002: Smart Copy 动图走临时文件引用 + 首帧位图兜底

- 状态：已接受
- 日期：2026-08-30

## 背景

聊天软件普遍无「剪贴板粘贴动图保帧」的官方规范（调研确认六款软件全部无可靠来源）。平台机制层面：位图/DIB/PNG/TIFF 流天然单帧，必丢动画；文件引用（Windows `CF_HDROP`、macOS `public.file-url`）是唯一可携带完整文件的通道。

## 决策

- 静态图（PNG/JPG/BMP/静态 WebP）：位图通道优先（Windows `CF_DIBV5`/`CF_DIB` + PNG 流；macOS `public.png`）
- 动图（GIF/动态 WebP/APNG）：文件引用指向**系统临时目录里的副本**（非库内原文件），同时附首帧位图兜底
- 临时文件生命周期：下次复制时清理上一批 + 应用退出时全清
- 动态 WebP/APNG 在 MVP 原样复制不转码；实测丢帧普遍则 P1 增加自动转 GIF

## 理由

- 指向临时副本而非库内原文件：不暴露库结构、无「粘贴方异步读取时原图已被删」的竞态、目标应用锁定的是临时副本
- 双格式写入：支持文件引用的应用拿到动图，只读位图的应用至少显示首帧
- GIF 是唯一被普遍支持的动画光栅格式，文件引用通道下保帧概率最高

## 后果

- 每次复制动图有一次文件拷贝成本（动图通常 ≤数 MB，可接受）
- 需要临时目录清理机制，避免残留堆积
- 动态 WebP/APNG 的实际保帧率待兼容矩阵实测（发布前 checklist）
